# 制作流程

这份文档按实际制作的顺序，列出每一步运行什么、产出什么、要注意什么。以下命令都在仓库根目录、Windows PowerShell 中运行：`py` 指 `.venv\Scripts\python.exe`，`blender` 指 Blender 5.2 的 `blender.exe`（`src/blender/drive_shots.py` 里的 `BLENDER` 写着它的路径，装在别处时改这一行）。另需 ffmpeg 在 `PATH` 上。

| 阶段 | 输入 | 输出（都在 `work/`，可删除重建） |
|---|---|---|
| 1. 音频分析 | `input/song.*` | `analysis/audio.json`（节拍、段落、响度、底鼓与军鼓） |
| 2. 歌词逐字时间 | `input/lyrics.txt`（+ 可选的卡拉 OK 轴） | `analysis/lyrics_timed.json` |
| 3. 角色素材 | `assets/char/prompts/` | `assets/char/<姿势>/` 分层素材 |
| 4. 三维镜头 | `src/storyboard.py` | `render/<镜头>/*.jpg` |
| 5. 合成 | 以上全部 | `segments/*.mp4` → `out/roshin_yuukai_mv.mp4` |
| 6. 审片 | 成片或静帧 | `qc/` 下的拼图与报告 |

## 0. 准备

```powershell
py -3.12 -m venv .venv
.venv\Scripts\pip install -r requirements.txt --extra-index-url https://download.pytorch.org/whl/cpu
py src\tools\fetch_fonts.py          # 从 google/fonts 下载用到的 OFL 字体
```

把你自己的原曲和歌词放进 `input/`（见 `src/paths.py`）：`input/song.m4a`、`input/lyrics.txt`（一行一句，段落之间空一行）。卡拉 OK 逐字轴 `input/karaoke.ass` 和 LRC 文件 `input/lrc/` 可选，只在重新对齐歌词时需要。

## 1. 音频分析

```powershell
py src\analysis\analyze_audio.py
```

第一次运行会用 ffmpeg 把原曲转成 `work/song.wav`。全曲是恒定的 165 BPM：十六分音符网格由鼓轨拟合，`timeline.py` 里的 `BEATS` 和所有踩拍特效都用它。`audio.json` 里的 `beats` 来自 librosa 的节拍追踪，它报出的是 110 BPM，是错的；只保留下来复现剪辑当初的切点吸附（见第 4 节）。

## 2. 歌词逐字时间

### 直接用仓库附带的时间轴（同一首歌）

```powershell
py src\analysis\apply_timing.py
```

`data/lyrics_timing.json` 记录了 55 句里每个字出现的时间和每个音拍落在网格上的位置，不含歌词文字。这个脚本把它和你的 `input/lyrics.txt` 合起来，生成 `work/analysis/lyrics_timed.json`。歌词版本不同（某句字数对不上）时会停下来，并告诉你是哪一句。

歌词本上没有、但唱出来了的词（例如段落间的呼喊），在 `src/storyboard.py` 的 `EXTRA_LINES` 里按卡拉 OK 轴的段号登记样式。合成时从卡拉 OK 轴读出它的罗马音，转成平假名，按音节时间显示；没有卡拉 OK 轴时跳过。

### 从头对齐（换一首歌时必须这样做）

依次运行 `src/analysis/` 下的脚本，人声分离和声学模型都在 CPU 上分段运行，可以断点续做：

1. `separate.py`：Demucs 分出人声、鼓、贝斯、其他四条分轨。
2. `readings.py`：每个字的读音拆成音拍。`FIX` 记录自动读音读错的字（按句、字的序号），例如唱成“わ”的助词“は”。
3. `pitch_track.py`、`melody_mask.py`：用 pYIN 提取主旋律音高，并做出只保留主唱谐波的旋律轨 `vocals_melody.wav`；把人声轨和 other 轨相加得到 `vocals_other.wav`（Demucs 会把副歌里加了效果的人声分到 other）。
4. `mms_emissions.py`，再加 `--src vocals_other`、`--src vocals_melody` 各跑一次：torchaudio 的 MMS_FA 模型逐帧算出字母概率。
5. `karaoke_ass.py`（有卡拉 OK 轴时）：解析 `{\k}` 音节，按罗马字对到每个音拍，并报告与当前时间轴的差异。
6. `mms_align.py`：整首的逐帧强制对齐，作为下一步的参照窗口。
7. `grid_align.py`：把每个音拍放到十六分音符网格上。证据来自字母概率、起音、旋律音高的跳变、清辅音的断声和句内的节奏先验；有卡拉 OK 轴时，它是主参照，每个音拍都被拉向它的卡拉 OK 时间，再由音频定到准确的十六分音符。
8. `lyrics_from_grid.py`：写出 `lyrics_timed.json`。每个字在它的音符前 0.07 秒开始出现；句尾按人声实际停下的时间（最后一个字至少停留 0.6 秒）。

校对：

- `py src\tools\audit_lyrics.py` 全曲审计：字落在持续的长音中间、起音附近没有字、人声还在句子已消失、与 LRC 句首偏差超过 0.6 秒。
- `py src\tools\qc_lyrics.py` 逐帧模拟字幕：每句是否按时出现、是否过早消失、同一位置是否重叠、竖排是否超出画面。

## 3. 角色素材

1. 提示词在 `assets/char/prompts/`。每个姿势都以三视图设定稿 `rin_ref_sheet` 为参考图生成：

   ```powershell
   powershell -File src\tools\codex_batch.ps1 -Names rin_serene,rin_teary
   ```

   脚本通过 Codex CLI 内置的生图工具出图（用 ChatGPT 登录，进程里删掉了 API key）。任何能接收参考图的图像模型都可以替代，关键在提示词：头发 6–9 束大发块、只留必要的褶皱、严格的两色硬阴影、统一线宽、中性光照、透明背景、人物不碰画布的左右和上边。

   成组的画（上楼梯的两帧）第二张要拿第一张当参考图：`-RefImages` 同时给设定稿和第一帧，提示词写明只改腿和手臂，头、发型、服装、在画布上的大小都照第一帧。重画一张时用 `-Version v2`，旧图留着对比。

   每个镜头都要有自己的画。`py src\tools\pose_audit.py` 列出每个镜头用到的原画和每张原画出现在哪些镜头：同一张画出现两次，只能是有意为之（片头片尾呼应、同一场连续的戏、线稿和实拍的对接），否则就给那个镜头生成新的姿势。
2. `py src\char\process.py <姿势>`：清理透明边缘、扁平化赛璐璐、生成伪法线 `normal.png`、轮廓光用的边缘带 `edge.png`，以及头发、皮肤、衣服的区域蒙版。
3. `py src\char\hair_weights.py <姿势>`：头发摆动权重 `hair_soft.png`。蒙版先闭合、填洞（发箍和发夹跟着头发动），离皮肤越远权重越大，再大幅模糊；这样头发整体柔和地摆，不会出现“两层头发”。
4. 闭眼版：`py src\char\blink.py <姿势>`。另一种表情（同一个姿势、身体不动）：先用 `codex_batch.ps1` 拿原图做一次只改眼睛和嘴的编辑，再 `py src\char\expression.py <原姿势> <新姿势> "cx,cy,rx,ry,角度;..."`，只把两只眼睛和嘴所在的椭圆区域对齐后补进原画，其余图层照原姿势复制，两张画可以在同一个镜头里切换。结尾醒来的 `rin_wake_morning`（睡姿原画加上刚睡醒的脸）就是这样做的。
5. 替换同构图的旧姿势：`py src\char\fit_card.py <新姿势> <旧姿势> <旧卡片高度>`，算出让双眼落在原位置的卡片高度和位移，原画保持原始分辨率；`align_pose.py` 会直接缩放像素，只适合缩放幅度很小的情况。
6. 原画的边被手臂或袖子碰到时：`py src\char\extend_canvas.py <姿势> <版本> <新版本> --pad 400 --slope 0.4`，左右对称加宽画布，沿手臂方向延长袖子，镜头调度不变。
7. 踩着拍子的动作（逐格换图）用两种画：成组的新画（0:49 弯腰、跪下、蜷倒的三张，第二、三张拿第一张当参考图，提示词写明头部大小照第一张），或同一张画只动一个部位的变体（打火机的拇指、垂下的手臂、晃动的脚、挥动的手）。变体先用 `codex_batch.ps1` 拿原画做一次只改那个部位的编辑，再 `py src\char\variant.py <原姿势> <新姿势> "cx,cy,rx,ry,角度;..."`：在椭圆以外对齐（仿射 ECC），只取椭圆里的部位，颜色和透明度都换；椭圆附近新画增减的轮廓（鞋尖、袖口）自动并入，免得留下旧肢体的碎片；处理完再把椭圆以外的每个图层拷回原姿势的像素，两张画换图时其余部分一个像素都不动。原画加宽过画布的（`extend_canvas.py`），在最后加上原画布的尺寸作为线宽参照。
8. 电视里主持节目的铃：`py src\char\silver_mic.py` 把原画里话筒的球形网罩提亮、手柄保持黑色（全黑的话筒贴着黑色水手领，整支提亮又和白衬衫印成一片，变成灰度网点的电视画面后都看不见），再用 `py src\tools\make_tv_picture.py` 重做房间电视的两张画面（挥手的两端，`rin_on_air.png` 与 `rin_on_air_wave.png`）。

## 4. 分镜与三维镜头

全片的分镜都在 `src/storyboard.py`：每个镜头的起点（多数落在切点吸附后的八分音符上）、场景、相机关键帧、角色卡片、特效、转场和歌词样式。剪辑当初的切点时间冻结在 `data/cut_timeline.json`，之后再精修歌词时间也不会移动切点。

场景模块在 `src/blender/`：`scene_room.py`（六叠小屋，床架在 `bed_frame`）、`scene_city.py`（程序化城市，布局在 `src/citygen.py`）、`scene_core.py`（托卡马克炉心）、`scene_dusk.py`（黄昏街道）、`scene_gears.py`（齿轮与擒纵）。床品在 `bedding.py`：被子和枕头由 Blender 布料模拟落定，躺着的铃身上的被子按她原画的轮廓隆起，坐着的铃身下床垫压出凹陷，结果缓存在 `work/cache/bedding/`。

镜音铃是一张张贴图卡片（`character.py`）：自发光着色器按伪法线打细轮廓光、按 `key_wash` 把主光做成覆盖整个人物的宽幅渐变（不在原画上另切一道明暗交界线）、眨眼换图、按 `hair_soft` 权重让发梢慢慢摆动、呼吸时卡片底边不动地轻微伸缩。卡片的常用参数：

| 参数 | 作用 |
|---|---|
| `face_cam` | `True` 只绕竖轴转向相机，`"full"` 完全朝向相机，`"screen"` 与成像平面平行（长焦大光圈特写用：整张脸在同一深度，不会只有一条横带清楚）：避免斜看时人物被压扁 |
| 相机 `focus="card"` | 对焦点挂在卡片上（`focus_at` 为卡片高度的比例，例如眼睛的位置），不再对在取景中心：相机从她身下仰拍、取景中心在她身后时，人物不会虚掉 |
| `tilt` | 躺在床上的卡片沿床身倾斜的角度：头的一端高过枕头，身体贴近床垫 |
| `stretch` | 卡片从底边起沿高度拉长的倍数。相机从高处往下看立着的纸片，人会显得矮胖，拉长约“1 / 俯角的余弦”就回到原比例；`card_angles.py` 会把它算进去 |
| `props` 里的 `sway`、`sway_rate` | 发梢摆动的幅度（原画 UV 单位）和快慢。幅度按镜头换算成屏幕像素来定：发梢摆 7–13 像素才能透过 5.5 像素的网点被看见；`sway_rate` 0.85 是微风，0.7 是失重漂浮 |
| `contact` | `dict(kind="lie")` 卡片下方一层柔和的轮廓阴影；`dict(kind="sit")` 坐姿：卡片下部沿相机视线后推，臀部和脚都落在被面上（`bedding.seat_card`），身下压出凹陷和贴着被面的阴影 |
| `on` | 逐格换图：卡片只在这些时间段（歌曲秒数）里出现，它的贴地阴影跟着一起换。同一位置放几张卡片轮流出现，换图落在两帧之间（`storyboard.swap_at`）；轮流出现的区间用 `storyboard.alternate(轮换点)` 生成，任何时刻都正好有一张画在场。配合 `motion=None` 或相同的 `phase`（呼吸相位），换图时卡片不会跳 |
| `keys` 的时间 | 关键帧的时间可以是镜头的比例、`("s", 秒)`（镜头内）或 `("t", 秒)`（歌曲时间）：踩拍的动作直接写拍点，比如 S09 在乐队的重拍上睁眼（`blink`）、S16 的主光在听得见的重音上亮一下（`storyboard.pulse_keys`，重音来自 `timeline.accents`） |
| `contact=dict(kind="floor")` | 站、跪、躺在地板上的卡片：原画最低的一行落在地板上，接触的部位下面一块柔和的阴影 |
| `props` 里的 `ink`、`floor_shade` | 床上的镜头用：`ink` 在她的外轮廓上压一道深色，`floor_shade` 让原画最下面五分之一（贴着床的脚和小腿）略暗。光脚和白床单一样亮，网点会把两者都印成纸色，脚看起来像被截掉 |

渲染：

```powershell
py src\blender\drive_shots.py all                          # 每个镜头一个 Blender 进程，可断点续渲
py src\tools\finish_pipeline.py --shots S23,S24 --pct 80 --no-comp   # 指定镜头；带体积雾的炉心镜头用 80%
py src\tools\finish_pipeline.py --tails S29,S31 --pct 100 --no-comp   # 只补渲切点之后的“尾巴”帧（给叠化用），镜头本身不重渲；--pct 与该镜头原来的分辨率一致
```

镜头之间默认是落在拍点上的硬切。让硬切顺的是两个镜头共有的东西：运动的方向和速度一样，或者眼睛正看着的那个形状在同一位置、同样大小（片名的光环与反应堆的光环、监测图上的光环与夕阳、夕阳与她的瞳孔）。转场写在 `storyboard.py` 的 `FLOW`，只用在画面本身给了理由的地方：光（乐队停下时变暗、音乐静下来时的黑、白色副歌褪成的白、炉心过热的白、日出的白）、同一张画变成另一张画（她和她的图解、结尾同一张画在同一推进下的叠化），以及片子开头的那个光环在静默里重画、在副歌上张开。静默后音乐炸开的三个重拍（1:08、4:19、4:33）是闪光，写在镜头里。第九、十版曾在每个换场的切点加叠化或推进穿越（全片四十多处、开场全部），看起来是一层叠在画面上的转场，又慢又不自然，第十一版全部重新判断。叠化要求上一个三维镜头渲染过切点（`TAILS`），这样它在叠化底下仍在运动。

| 转场参数 | 作用 |
|---|---|
| `in_anchor=(x, y)` | 推进穿越朝画面上的这一点推（默认画面中心）：上一个镜头正飞向的光源、太阳、她的眼睛或胸口 |
| `in_radial=True` | 新镜头从锚点向外柔和展开，而不是整幅叠在旧画面上；两张不相干的画面不会互相压着 |
| `in_push` | 推进穿越时旧画面放大多少（默认 0.3） |
| `in_bloom` | 叠化中途提亮一下，像漏光 |
| `in_r0` | 圆形展开从这个半径开始，例如上一个镜头画出的光环本身张开 |
| `in_pre` | 推进穿越在切点前多少秒就开始推（默认 `in_dur` 的 0.6 倍），速度的峰值跨在切点上，不会切点后突然一冲 |
| `out_anchor`、经白或经黑时的 `in_anchor` | 白场或黑场从这一点长出来铺满画面（炉心的光、楼梯的灯），下一个镜头再从对应的点向外浮现 |

切点要落在听得见的鼓点上，不只是网格上：分镜解析把切点吸到八分音符网格以后，若那一帧不在 0.6 以上的鼓点上，而 0.35 秒内有 0.75 以上的重击，就移到那一下（`timeline.hit_near`，起音和低频取大者打分）；一次性的动作落在镜头里起音和低频一起最重的那一下（`timeline.strongest_hit`）。`py src\tools\cut_hits.py --all` 列出每个切点附近的鼓点和判断。

锚点按两边画面里同一个东西的位置来定：用 `render_comp.py --stills <秒,...>` 出切点前后几帧，在网格上量出位置。`in_anchor` 之类的值只影响合成，不用重渲。

**匀速推进。** 片名、结尾和全片其他往前推的镜头要像一个镜头一直匀速往前推，靠这几样东西（开场的飞行另有一条按音乐分段变速的路径，见下文“开场的一镜到底”）：

- 机位用 `ease="dolly"`：到注视点的距离每秒按同一比例缩短，焦距按同一比例变化，画面放大的速度从头到尾一样。线性移动在画面上是越推越快的，因为越靠近，同样的位移放大得越多。
- 二维镜头的推进用 `{"type": "zoom", "rate": PUSH}`（每秒按同一比例放大），眼睛特写用 `bg_args` 里的 `zoom_exp=True`。片名的光环用 `storyboard.PUSH = 0.22`：每秒约 22%，切到反应堆时三维的光环从同样的大小、同样的速度接着沉下去。前奏 0:07.62 起是满能量的 165 BPM，每秒 12–14% 的推进配叠化看起来又慢又拖（第十版）；速度要和音乐的劲头相称，同时在一段里保持同一个值。
- 推进按画面实测，不按注视点算：城市俯冲里近处的高楼比注视点近得多，按地面设的机位在画面上快到 33%/秒；俯视城市时要按楼顶（约 100 米高）而不是地面设注视点，否则越往下越快。先出低分辨率预览（`drive_shots.py preview=1 pct=30 step=2`），在预览帧上量，再按比例调机位。房间里的镜头，窗外远处的灯不随推进放大，整幅画面测出来偏低，要只量人物所在的区域。
- 切点上不额外加推：两个镜头各自按同一速度往前。也不做数码局部放大（把已渲染的画面裁一块放大）：主体会被切掉一半，第十版桥段的加速剪辑就是这样被指出来的。
- 推到最后要停的镜头加 `settle=<秒>`：开始时接住上一个镜头的速度，速度按这个时间常数指数衰减，平滑地停在终点。结尾 S65c 用 2.9 秒，从每秒约 11.7% 开始，十秒内停稳在她脸上。
- 叠化底下两个画面要一起动：`drift=(vx, vy, vz)` 让注视点以上一个镜头结束时的速度（米/秒）出发，再平滑停在终点。结尾 S65b 承接 S65 的横移，到切点时停住；S65c 从静止出发，慢慢漂到最后的构图。速度是否连续，可以把相邻两个镜头的机位函数在切点两侧各取一点比较。
- 线性机位（`ease="linear"`）也能接住上一个镜头的漂移：`aim_v0=(vx, vy, vz)` 是注视点出发时的速度（米/秒），之后沿三次曲线走到终点，到达时的速度和原来的线性移动一样，所以尾帧和下一个切点都不变。S06 用它让反应堆的光环在叠化中停在 S05 窗里的位置。

速度用 `py src\tools\push_speed.py 0 34` 测：逐帧算画面的放大速率并画出曲线，标出切点。三维镜头最好在原始渲染帧上测，成片里不动的读数和片名会把数字拉向零。

要把上一个镜头里的某个东西（她的脸、眼中的太阳）推到下一个镜头里同一个东西的位置和大小上：量出它在旧画面里的位置 p、在新画面里的位置 p′ 和两边的大小之比 s，取 `in_push = s − 1`、`in_anchor = (s·p − p′) / (s − 1)`，不加 `in_radial`。锚点可以在画面外，这时旧画面边放大边平移，正好落到新画面上。两个镜头没有共同的东西、观察方向又急转时（俯视城市接正面炉体、楼梯接卧室），不硬推，改用有光源依据的闪白、经白场或经黑场。

单个 Blender 进程的内存峰值约 3.4–3.7 GB；16 GB 内存的机器上一次只跑一个。

**开场的一镜到底。** 从片名到她睁开眼睛是一个镜头（`src/blender/flight.py`），城市（S03）和房间（S09）两个场景用同一条机位路径：

- 路径在城市坐标里定义，`opening(t)` 给出歌曲时间 t 的位置、朝向和焦距。她的窗（`WIN_C`、朝向 `N`）就是当初渲染房间窗外城市背景板的位置，`room_to_city` / `city_to_room` 经这扇窗在两个坐标系之间换算；分镜里 `cam=dict(path="opening")` 用城市坐标，`frame="room"` 用换算后的房间坐标。
- 速度按音乐分段：在片名的光环上方以 `PUSH` 的速度下沉，加花上抬镜（`T_TILT0`–`T_TILT1`，鼓点落在城市展开时），滑翔过海湾（署名，`R_GLIDE` 每秒约 32%，目标楼在这段里长成主体），加速到镲片（`T_ARC`），减速着陆到窗台下方（`AIM`、`T_SWITCH`），仰看着天花板的环形灯升进窗（`WINDOW_IN`、`T_ENTER`、`LAMP_CITY`），往下转到她上方停稳（`T_SETTLE`，她在这一拍睁眼）。她是一张平放在床上的画，镜头只能在几乎正上方看她：她躺在窗台下面，镜头在窗外时视线被墙挡住，穿窗后她在偏离正上方 30° 以内才入画；她始终在床上，不靠隐藏。用 `path_card_angles.py` 检查（含窗墙遮挡）。推进用“画面放大的对数速率”描述，峰值按“着陆时离窗多远”反解，改任何一段都不会让终点错位。改路径后用 Blender 跑一遍探针，打出每半秒的位置、速度和转角，确认没有穿楼、没有失速。
- 窗洞（portal）：带 `portal="WINDOW_CORNERS"` 的镜头渲染时把窗洞四个角逐帧投影到画面上，写进 `work/render/<镜头>/portal.json`；下一个镜头用 `in_="portal"`，合成器在这个轮廓里显示房间、轮廓外显示城市（城市镜头要渲染过切点，`TAILS`），任一角到了镜头背后就只显示房间。城市画面里她的窗上不放任何发光的玻璃（会在轮廓外露出一圈亮边），房间里镜头穿过的那扇玻璃隐藏（`hide` 里的 `Pane0`）。
- 房间从外面看要像一扇亮着的窗：`anim=dict(exposure=[(秒, 档), ...])` 按歌曲时间给相机曝光打关键帧，窗外高 1.2 档，窗口铺满画面时回到房间的夜色。
- 片名接进三维：`fx` 里的 `ring_over` 把片头的二维光环按同样的推进画在三维光环上，再淡出；`ink_from=(印刷, 起, 止)` 让上一个镜头的印刷方式越过切点、按歌曲时间过渡到本镜头的；`hud` 的 `fade=(起, 止)` 让控制台淡出；二维光环的 `settle` 让它在切点前停止呼吸；`PRE_BLUR` 可以写成随镜头进度变化的关键帧。切点两侧的环用 `render_comp.py --stills` 出帧，按一行像素量线宽和亮度。

**踩着拍子的演出。** 全片的铃在几处跟着音乐做动作，用的都是逐格换图。时间点不从节拍网格上取，而是取听得见的重音：`timeline.accents(t0, t1)` 从音频的起音包络里找峰值（同一段里两个重音至少隔 `gap` 秒），这首歌的重音大多在一拍或三拍的后半拍，按网格的一、三拍换图会和耳朵听到的错开。一次性的动作只换一次图、做完保持：0:44 拇指在唱到“打火机”的重音上擦一次火石（火花在这一下迸出，`sparks` 的 `hits`；之后 `sputter` 让火石口在十六分音符上断续冒小火花到镜头结束），3:37 和 3:48 起耳鸣里一张一张缩紧（`tinnitus` 的 `steps=[(画, 秒), …]`：每个镜头三张画，每张在一下有分量的重击上整张换上并保持，波形随之涌起；不做中间画，那会像动画）。会重复的动作跟着那一段自己的律动：0:49 两个最强的重音上跪下、蜷倒（胃里的光 `anim glow` 也在重音上亮），2:46 晃脚在每小节的第一拍和第三拍的后半拍，3:12 起电视里的她只在唱“电视主持人”那一句的重音上挥手（`storyboard.WAVE`，房间 CRT 的 `anim crt_wave`、二维雪花电视和电视墙的 `wave`），唱完就停。0:27 在乐队的重拍上睁眼，0:31 唱出第一个字时手贴上窗玻璃，1:46 上楼梯，5:18 醒来。换图都落在两帧之间；同一张画的变体除了动的部位一个像素都不变。取景时把人物最高点（蝴蝶结）和手脚在整个推进里的位置算出来，保证站着、跪着、躺着时都完整在画内。`pose_audit.py` 逐帧检查每个逐格换图的镜头都正好有一张画。

**楼梯上的定格动画。** S31 的铃每一拍上一级台阶（`scene_dusk.climb`）：两张上楼的画（左脚抬起、右脚抬起）轮流出现，每拍换一张并整体上移一级，换图和移动都落在两帧之间，任何一帧都不会被运动模糊拖出残影；落到新台阶上时卡片轻轻压一下再弹回。她踩着的那一级的边缘同时亮起来。另有两张只投影子、相机看不见的卡片转成正对太阳，跟着同样的关键帧，把她的影子投在旁边的墙上。

**画面自己的变化也踩在音乐上。** 没有歌词的地方，画面要让人眼看得到变化（导演说的“留白”：画面放着，只有效果或只有缓慢的运镜）。1:37 的间奏里，镜头接着地图的推进均匀推向反应堆，光环在四下重拍上一亮一收（黄昏场景的 `anim ring_pulse`）；2:53 看电视的间奏里，雪花在重音上闪出她自己的脸（房间的 `anim crt_glimpse`：几帧主持人的画面，电视的光跟着一跳；合成的 `strobe` 给出同样的时刻 `hits`），她在积累后的重拍上抱起膝盖，近景里眼睛在小节重拍上转向钟。有歌词的地方，画面也可以跟着音乐变：2:00 城市在六下重音上一格一格融下去（`melt` 的 `steps` 和 `to`）。`py src\tools\pace_report.py` 在成片里估计整幅画面的运动（特征点的稳健拟合，闪烁、雪花、闪光是离群点），从分镜里读她的动作，没有歌词、没有动作、画面又几乎不动的镜头报警。

## 5. 合成

```powershell
py src\comp\render_parallel.py --workers 3               # 每个镜头合成一个分段，再拼接并混入原曲
py src\tools\stale_segments.py                           # 列出渲染帧比分段新的镜头（含转场里用到的上一镜）
py src\comp\render_parallel.py --workers 3 --redo S23,S24   # 只重做改过的镜头（相邻分段会自动带上）
py src\comp\render_comp.py --stills 12.5,70               # 只出指定时间的静帧
py src\tools\encode_share.py                             # 分享版：x264 crf 19，约为母版一半大小
```

合成器（`src/comp/`）每一帧的顺序：Blender 渲染帧或二维镜头 → 镜头特效 → 印刷质感（`printlook.py`：调幅网点、专色、套色错位、纸纹，副歌的“烧穿”）→ 歌词与控制台读数（`typo_fx.py`、`hud.py`，按背后画面的明暗换墨）→ 转场（溶解、推拉模糊、光圈、闪白、窗洞）→ 颗粒与调色（`finish.py`）。单个合成进程约 1.1 GB。

**线稿和实拍要对得上。** 人体线稿镜头（S15b、S55）用的就是前一镜或后一镜的那张原画，按透视铺在对方的画面上：`blender -b --factory-startup -P src\tools\card_quad.py -- S56:6434` 读出卡片四个角在那一帧画面里的位置，填进 `chest_core` 的 `quad`；线稿自己的推进用 `push=dict(z, about)`，每帧按放大后的尺寸重新画，不去放大成品画面（绕画面外的点放大成品画面，边外的部分只能靠镜像补，圆环会多出一个倒影）。换成叠化后，线稿和她的身体在切点处重合。

## 6. 审片

| 工具 | 用途 |
|---|---|
| `py src\tools\review_sheets.py --every 1` | 不编码视频，按秒合成带时间、镜头号和歌词标注的拼图，几分钟看完全片 |
| `blender -b --factory-startup -P src\tools\card_audit.py -- S05,S14` | 把铃的原画每个不透明像素投到画面上：被什么挡住、原画的边是否露在画面里、离身下的表面有多高。`py src\tools\card_audit.py --all` 检查全片 |
| `py src\tools\pace_report.py` | 找“留白”：每个镜头整幅画面的运动（特征点稳健拟合，效果不算）、分镜里她的动作、有无歌词；乐队在演奏而画面没有变化的镜头报警，安静处的列出来由人判断 |
| `py src\tools\cut_hits.py` | 每个切点是不是落在一下听得见的鼓点上（`cut_report.py` 只量网格）；错过附近重击的切点报警 |
| `py src\tools\card_angles.py` | 每个镜头里卡片与视线的夹角，查斜看导致的压扁 |
| `blender -b --factory-startup -P src\tools\path_card_angles.py` | 路径机位（`flight.py`）逐帧算卡片在画面里时视线偏离它正面多少度，超过 35° 报警：平放的画被斜着看就是一张纸 |
| `py src\tools\cut_sheet.py 0 34` | 每个切点前后的帧并排，判断转场 |
| `py src\tools\cut_report.py` | 每个切点的亮度和颜色跳变、离节拍网格多远、是否切在一句歌的中间，用来找生硬的转场 |
| `py src\tools\film_review.py` 加 `src\tools\codex_review.ps1` | 把每个镜头的三帧拼成审片图，交给视觉更强的模型逐镜挑错（提示词示例在文档末尾） |
| `py src\tools\qc_video.py` | 成片时长、黑场、卡帧 |
| `blender -b --factory-startup -P src\tools\flip_scan.py` | 每个三维镜头的相机逐帧检查：画面朝向有没有突然转过 20° 以上（正上方俯拍时 Blender 的朝向解会跳） |
| `py src\tools\qc_dynamics.py` | 画面运动、亮度与响度、节拍、歌词画在同一条时间轴上 |

审片的原则：每发现一个问题，就在全片里找同一类问题一起修，例如原画的边露在画面里、人物陷进家具，不只修被指出的那一处。
